# Testing Artemis

## The self-test harness

Artemis tests itself from the inside. `SelfTest` (in `Artemis/models/SelfTest.swift`) runs a suite against the **running app** — live `WKWebView`s, the real content blocker, the real on-disk stores — rather than against mocks.

Run it from the repo root:

```sh
# build, run the suite, read the report
xcodebuild -scheme Artemis -configuration Debug -derivedDataPath .build build

pkill -x Artemis; sleep 2   # quits every copy of Artemis, the one you browse with too
ARTEMIS_SELFTEST=1 .build/Build/Products/Debug/Artemis.app/Contents/MacOS/Artemis &

# a few minutes later, once the app has quit itself
cat ~/Library/Logs/Artemis/artemis-selftest.log
```

The build needs Xcode 27. If `xcodebuild` picks up a different Xcode, point `DEVELOPER_DIR` at the right one first, for example `export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`. `deploy.sh` and the lab scripts honour the same variable, and sign with `ARTEMIS_SIGN_IDENTITY`, falling back to the identity in an untracked `.signing-identity` file at the repo root, then `Apple Development`.

The suite has finished only if the log ends with a `done` line. A log without one stopped early, whatever its tally says.

The log is appended to as the suite runs, so a hang or crash still leaves the results up to that point. Each run overwrites it.

Everything the developer hooks write lands in `~/Library/Logs/Artemis/`: the self-test log, the accessibility dump (`artemis-ax-dump.txt`), every `ARTEMIS_DIAG` report, the bench log (unless `ARTEMIS_BENCH_DIR` is set) and the tab-name corpus and sweep files. Nothing goes to `~/Downloads`. The extension lab keeps its queue, packages and results in `~/.cache/artemis/extlab/`.

To run only some groups, name them: `ARTEMIS_SELFTEST=reports,routing`. A group's name is its `test…` function's name without `test`, lowercased (`testWebNotifications` is `webnotifications`). The table in `SelfTest.run` lists them in order. Some groups rely on state an earlier one leaves behind, so a group that fails alone may pass after its predecessor.

The suite gives the screen back to whoever is using the Mac. Before the first group and between groups it looks for real keyboard, mouse or trackpad input in the last 60 s. If there was any, it hides the app, waits until 60 s pass with none, then unhides and carries on. A bench does the same once, before its first step. It never stops inside a group or a timed loop. Each pause writes a `pause <epoch>` and a `resume <epoch>` line to the log. `fin-away --paused <log>` totals them, and `artemis-labtest`, `tools/bench-gate.sh` and `tools/test-impact-map.sh` leave that time out of their timeouts. They also wait for 60 s without input before they launch a lab. A lab started with `ARTEMIS_PAUSE_FILE=<path>` creates that file when it pauses and deletes it to resume. A runner that moves the file away holds the pause, which is how those scripts lend the lab's `heavy-job` slots to queued builds (`heavy-job --lend`) and take them back before the suite goes on. Input posted with `CGEvent.postToPid` or to the session tap does not count. Input posted to the HID tap does, and so does touching `~/.cache/artemis/fin-here`, which is the way to test a pause.

`tools/perflab.sh` builds a copy under its own bundle id and data folder, so a lab run never touches an installed Artemis. `PERF_CONFIG=Debug tools/perflab.sh` builds Debug instead of Release, which is much quicker when iterating on a test. Then start it with `tools/perflab.sh --run ARTEMIS_SELFTEST=<groups>`. A lab copy named `Artemis <ID>` writes its report to `~/Library/Logs/Artemis/artemis-selftest-<ID>.log`, and every other file it writes there carries the same `-<ID>` suffix, so lab runs and a run of your own never overwrite each other.

A lab launch asks no list host, so `--run` gives the lab the shipped app's block lists itself. It copies them from `~/.cache/artemis/blocklists/`, which one fetch a day keeps current, into the lab's data folder, then returns once the lab has compiled them and prints the rule count. A bench waits for that compile before its first step and writes the count in its log. `tools/bench-gate.sh` seeds each arm the same way. A self-test launch is not seeded: it starts on the starter list, and the groups that need real lists fetch them.

### Running only what a change reaches

`tools/test-impact.py select` reads the branch's diff against `stable` and prints the groups that diff can reach, `1` for the whole suite, or `none`. `artemis-labtest <tree> <ID> auto` runs that selection. It is for iterating on a branch. A merge into `stable` and every nightly still run the whole suite.

The answer comes from `tools/test-impact-map.json`, a measured map. A coverage build (`PERF_COVERAGE=1 tools/perflab.sh`) runs the whole suite once and writes each group's counters to a slice of their own (`Coverage.mark`). Then every bench loop does the same. `tools/test-impact-map.sh` does all of that and rewrites the map from the commit it is on. Regenerate the map after big merges. `select` warns once the map is 50 commits behind.

A changed line selects the groups that ran its function. Blank lines, comments and lone closing brackets select nothing. A line a nested closure starts or ends on also counts as part of the function around it. A line changed since the map was made is placed by the unchanged lines either side of it. If the map is newer than the whole change, its new code selects the functions it sits inside. The whole suite runs in these cases:

- a line the map still can't place;
- code that only runs at launch;
- the project, `Info.plist`, entitlements or `tools/perflab.sh`;
- a file neither the map nor any mapped code names;
- a selection over half the groups.

A line outside every function, such as a stored property, selects every group that ran a function of its type. At the top level of a file it selects the whole file. New `private` members and new types select nothing until a changed line uses them. A new `override` or `@objc` member selects every group that ran its type, because AppKit calls it without any changed caller. A Swift file with no functions, or a resource such as `Readability.js`, takes the groups of the code that names it. In `SelfTest.swift`, a changed table entry or `test…` function selects its own group. A helper added there selects nothing until a changed test calls it.

### The perf check before hand-off

`tools/bench-gate.sh` is the standard perf check for a merge. A lane runs it on its finished branch before handing the branch over, and puts the verdict lines in the hand-off.

```sh
tools/bench-gate.sh                  # the loops the change reaches, 3 runs an arm, against stable
tools/bench-gate.sh tab,space 12     # named loops, 12 runs an arm
BASE=<sha> tools/bench-gate.sh       # against another base
```

- **Base.** `stable`, or `BASE=<ref>`. The base's Release lab is built once per sha and kept in `~/.cache/artemis/bench-stable`. The branch's lab is built from the tree as it stands, so commit first.
- **Loops.** With no argument, `test-impact.py select --perf` names the loops the diff reaches: `tab`, `tab2`, `space`, `sidebar`, `bar`, `newtab`, `load`, `idle`. If it names none, the gate passes at once.
- **Runs.** Each loop runs both arms interleaved, 60 s a run, the two arms taking turns going first. Run the gate directly, not inside `heavy-job`. It takes `heavy-job --both` for each block of 3 runs, then the screen lock with `lockf -t 0`, and gives both back while someone else has the screen or the Mac is in use. Before each run it waits up to 5 minutes for the 1-minute load to fall under 8. A run that still starts at 8 or more is dropped and counted in the report.
- **Verdict.** Per loop: `ok` or `FAIL`, the two medians of main-thread busy per step, the change, the loop's band, a permutation `p` and the runs per arm. A loop fails when the branch's median is above the base's by more than its band, a percent of the base's median, measured by `--aa` (the table in the script). Exit status 1 means some loop failed or had no result.
- **A close call.** If a loop fails with `p` above 0.05, run that loop again with 12 runs before acting on it. The raw runs of the last gate are in `/private/tmp/artemis-perf/bench-gate-runs.txt`.

`tools/bench-gate.sh --aa [runs]` runs the base against itself on every loop to measure the bands. Measure them again after `Bench.swift` changes. Both arms of a comparison must run the same `Bench.swift`, so a base from before a harness change is not comparable.

Test pages use `.example` and `.test` hosts, never `.local`. A `.local` name is looked up on the local network, which makes macOS ask every new lab copy for Local Network access.

**Where its data goes:** a build from source keeps its data in `~/Library/Application Support/Artemis`. The released app uses `~/Library/Application Support/app.artemisbrowser.Artemis`, so the suite never touches the browser you use day to day.

**Signing:** the build is signed to run locally, which is all the suite needs.

**Why run it directly rather than via `open`:** `open` launches through LaunchServices, which doesn't pass environment variables through.

## What it covers

Assertions across: durable storage and `.bak` recovery, session snapshot/round-trip/tolerant decoding, the zoom store and live page zoom, engine-level mute, media-state aggregation across frames, ranged history and archive clears, the Adblock→WebKit converter (including "does WebKit actually compile this"), **live blocking inside a real page**, the privacy cleaner, printing, hibernate/wake, reader extraction and the live reader toggle, backup capture and idempotent re-merge (a second profile restoring onto a machine without it, a profile only this machine has surviving with its favourites under ids no restored tab holds, a backup from before profiles still restoring), cross-space tab moves, the space creator's model path, profiles (each one's own jar, favourites, history and passwords; moving a space between profiles; migrating isolated containers; deleting a profile), incognito windows' no-trace guarantees (a non-persistent jar per window with no extensions, history/zoom/undo/session-snapshot exclusion, Peek inheriting the private jar, the Touch ID setting), undo and redo, window-chrome geometry, the traffic lights living in the sidebar, performance budgets, and a layout pass over every Settings pane (the rest of the suite is model-level, so a pane that crashes on construction would otherwise only surface when a human opened Settings).

Suites that drive the real thing rather than a model in isolation:

- **`panels`** — the file picker and JavaScript dialog delegates. A live page's `confirm()` reaching the panel and its answer reaching the page; `prompt()` carrying its default in and typed text back; a cancelled prompt arriving as `null` rather than an empty string, because sites branch on it; a page that spams `alert()` earning a suppression checkbox and then _running on_ instead of hanging; silencing being cleared by a navigation; an abandoned dialog still answering WebKit's handler. Two assertions check selectors rather than behaviour — `webView:runOpenPanelWithParameters:…`, the SPI `_webView:runBeforeUnloadConfirmPanelWithMessage:…`, and `_acceptedMIMETypes`/`_acceptedFileExtensions` — because WebKit dispatches by selector and a rename is not a compile error, it is a silently dead delegate.
- **`schemes`** — which url schemes stay in the browser, which are offered to another app, and which (the shell-reaching ones) are never offered at all; the per-site-and-scheme allowance round-tripping and being cleared with site permissions; and a live `mailto:` navigation raising the offer. The live half always answers _no_, deliberately: a yes would launch Mail on the developer's machine.
- **`files`** — a typed path resolving to a file url while a non-existent one stays a search, and a real local page rendering through `loadFileURL`.
- **`durable`** — the rotation under concurrent writers (24 tasks writing 200 KB each, then asserting both the primary and the backup still decode), and a per-store recovery drill: each of History, Archive and Zoom is built against a scratch file, written twice, has its primary replaced with garbage, and is reopened. A store on the rotating path comes back with the first write; one writing plain atomic comes back empty.
- **`session v2`** — tab records carrying the live tabs' own ids through an encode/decode cycle, the selection stored by id, the derived v1 mirror agreeing with the records (so the file still opens on an older build), and a hand-written v1-only blob decoding into records with freshly minted, distinct ids and its `selectedIndex` becoming a `selectedTabID`.
- **`boostsdormant`** — Boosts are kept but never applied: a scripted Boost saved to disk, carried by an exported backup and brought back by restoring it, each unchanged, while a page on its site loads with neither its script nor its CSS.
- **`tab names`** — a typed name living on its tab: two tabs on one page keeping different names, the name holding through the tab's own navigation, pin and unpin, a trip through the favourites, hibernation, a move into another profile's space, ⇧⌘T and the archive, and riding on the tab's record. A session this build writes is checked to carry the marker an older build drops. The hand-over from the url-keyed file runs against scratch files, then an unreadable and an empty one. Untested: that launch and a backup restore run the hand-over only when the marker is missing.
- **`favourites`** — a favourite as a record: its home is the page it was added on, closing it sends it there and leaves it in the grid, and its id, home and name survive an encode and decode and a reload through the launch path. The file this build writes is read back with an older build's shape (homes and names side by side) and rewritten in it, which keeps each home, and a hand-written older file loads with each page as its home and fresh, distinct ids. Away from its home a favourite reads as off it and its menu offers Make This the Favourite's Page, which makes the page its home through an encode and decode; at home the menu leaves it out. A real tile in an offscreen window is then clicked through AppKit, and away from its home it draws no off-home slash: a click anywhere on it, count badge included, only selects it and never reloads its page, at home or away. Back to Favourite's Page, from its menu and from the command bar, takes one that is away home, and neither offers it at home. A double-click goes home when away, from another tab or on the shown tile, loading the home once; at home it refreshes the shown tile, but a pair whose first click switched to the tile or woke it from sleep only selects it. A ⌘-click anywhere on an away tile opens the page in a new tab at the foot of Today and takes the favourite home. On a favourite already at its home, going back only selects it and splitting it off does nothing, and the page stays loaded. A loopback page in a favourite: a link to another site opens in Peek with the favourite left where it was, a same-site link navigates it, ⌘ still opens a tab behind, a target=_blank link still opens a new tab, the page's own move to another site is left to it, the setting off lets the link navigate, and a pinned tab sends its other-site links to Peek too. Each space then remembers what it last showed: another space in the profile lands on its own tab and coming back shows the favourite again, as does a round trip through another profile's space; a swipe shows the incoming space's remembered page before it settles; the session saves the favourite each space showed (a file without one decodes with none) and reloading the session lands on it; and closing the favourite clears every space's memory of it. Untested: the tooltip, which needs a real pointer.
- **`pinned`** — where a pinned tab reads as at its home. Its home's page taking itself elsewhere with no press behind the move is still home: a script redirect and a posted form as it loads, a redirect that fails before anything shows, and an address rewrite 21 s after loading, which the group waits out. A pinned row an older build saved off its home with no landing loads as at home, and a file this build writes carries the marker that keeps such a row off. Still off home: a load of another page of the site, a page gone to after a press, a step forward through history, and a move to another site long after loading. Untested: a press that follows a link in the page, and a swipe through history.
- **`tabstate`** — a blob round-tripping, an oversized one being dropped rather than written, the orphan sweep keeping the right file, and the end-to-end case: a real loaded tab's `interactionState` written under its id, then a tab constructed with that same id adopting the blob and replaying it on wake.
- **`detached`** — a Scout page joining the weak registry, being reachable from `allTabs`, mapping back from its web view, never being persisted, and being released when the last strong reference goes.
- **`auth`** — the disposition each authentication method gets, driven against the real delegate with a hand-built `URLAuthenticationChallenge` and no network: server trust left to the system, basic and digest raising a login that carries the realm and the host, signing in handing back a `.forSession` credential with the typed username and password, and cancelling actually cancelling rather than falling through to a handler that answers the server with nothing.
- **`handoff` / `translate`** — what Handoff refuses to advertise (an incognito page, a local file, nothing at all) as much as what it offers, and the page's own selection reaching the translation popover: nothing selected translates nothing, a real selection comes through exactly, dismissing clears it. The popover itself is system UI and isn't asserted on.
- **`import`** — both bookmark formats parsed from bytes the test writes itself: entity decoding in titles _and_ urls, nesting flattened rather than dropped, a bookmarklet that isn't a url skipped, an empty folder making no space, and a file that is neither format refused. Then the translation against the real `TabManager` — one space per folder plus one for loose links, everything pinned, everything but the page you land on still lazy, and the filed title becoming the tab's name. Importing again while a favourite is off its home adds no second copy, here and in `arcimport` and `browserimport`, and neither does importing while a favourite's page is the link but its home is elsewhere, here and in `arcimport`.
- **`folders`** — the sidebar tree against the live `TabManager`. An empty folder existing and drawing a row (it is a place you made, not a grouping the tabs implied, so it survives being emptied); tabs filing into it and the flat `space.tabs` order following the tree; collapsing hiding the rows while keeping the membership, and a ⇧-click range refusing to reach into a folded folder; nesting, and a folder dropped inside itself being refused rather than making a cycle the flatten would walk forever; ⌘⇧K sparing what's filed. Then the repair pass, which is the load-bearing half: a dangling entry dropped, a tab the tree never heard of adopted rather than lost, a duplicated entry collapsing to one row. Then ungroup lifting children into the folder's slot, close-folder taking its tabs with one ⇧⌘T bringing folder _and_ tabs back, and the round trip — empty folders, names, fold state and nesting all surviving an encode/decode, and a deliberately corrupted tree costing the folders rather than the whole session.
- **`certs`** — that an exception can't be minted for a host whose certificate was never seen (with nothing to scope it to, refusing is the only honest answer), that an unstored exception is never applied, and which failures are offered a way past: untrusted / bad date / unknown root yes, "couldn't find the host" and anything from another error domain no.
- **`undo`** — ⌘Z's routing and what it takes back, in a scratch space. Routing: the sidebar reaching the window's stack, from a popover off the window too, a text field, the inspector's web view, Scout and an unregistered window keeping their native one, and the menu title following focus. With real ⌘Z events (skipped when the window isn't key): a page's focused textarea keeping ⌘Z and undoing its own typing, and a page that calls `preventDefault()` on ⌘Z keeping it while the browser stack stays as it was. Then a close coming back to its slot, redo closing it again, and ⌘Z and ⇧⌘T using up one shared record; a selection, Close Tabs Below, Delete Folder (nested and empty folders included), Clear Today's Tabs and an archived pin each coming back whole, out of the archive; ⌘W on a pin waking back on its page; a removed favourite returning to its slot, home and name. Layout: moves, pins, folder and favourite moves, a cross-space move keeping its web view, split create, link, add, remove and unsplit restored under their ids, a restore skipping a tab closed meanwhile while keeping one opened meanwhile, Close Split coming back tiled, a pin's home going back, Stop Updating going back, undoing New Live Folder taking its rows along, and one window's ⌘Z leaving another window's later move alone. Renames of tabs, folders and spaces (a tab's still undoing once a reopen brought it back as a new object), space icons and themes, with a theme preview registering nothing. A deleted space returning at its index with its tabs, folders and routing rules, and redo deleting it again; New Space undone with its redo named for it. Scope: trimming the closed stack dropping its ⌘Z entries, an incognito window keeping no closes and nothing once it closes, and clearing or deleting a profile emptying every stack. `settingsundo` covers a Settings binding undoing and redoing, the pane it was made on coming back, an unchanged value registering nothing, and nothing registering on either stack while a browser window is key. Untested: a slider drag coalescing, which needs a held mouse button.
- **`bulk`** — the selection reading back in list order, each verb (pin, unpin, mute, unmute) taking the whole selection and then clearing it, a bulk close removing every selected tab and stamping them with one `ClosedAct`, and a single ⇧⌘T bringing the whole group back and emptying it off the stack.
- **`notifications`** — Artemis' own `window.Notification` shim: absent in an insecure page; in a secure one a frozen `EventTarget` class starting at `"default"`; `requestPermission()` without user activation prompts nobody; posting while unallowed fires `error`; an app-evaluated (activated) request reaches the prompt and a refusal reaches the page as `"denied"`; a remembered allow reads `"granted"`, and the same site reads `"denied"` in incognito. Nothing is allowed for real, so macOS is never asked for authorization.
- **`scripting`** — the AppleScript dictionary through a child `osascript`, so every line is a real Apple Event round trip (an app scripting itself raises no Automation prompt): reading a tab, its window and its space by id; `execute` refused while Allow JavaScript from Apple Events is off and a `javascript:` URL refused regardless; JavaScript values coming back as text, lists and script errors; setting the URL and mute; `make new tab` and `close`.
- **`downloads`** — a clicked download link finishing under its own name with no `.download` partial left behind, and staying on the sidebar's shelf for a moment after it finishes. During a self-test run downloads land in the temporary folder, because WebKit writing to `~/Downloads` raises a Downloads folder prompt for a lab copy.
- **`feedback` / `reports`** — an incognito window's feedback carrying no page or screenshot while an ordinary one sends what was ticked, an error report carrying the server's fields, a crash grouping across builds by the frames outside Artemis, the outbox keeping only the newest reports, a lab copy's bundle id starting no reporter however it was launched, and a raised Objective-C exception logged once with its name, redacted reason and throw site: the reason left out while an incognito window is open, and a long one clipped before it is redacted.
- **`incognito extensions`** — an extension reaching an incognito window only when allowed, `"not_allowed"` staying binding, and a closed incognito window leaving nothing in the runtime.
- **`window drag`** — a press on the page's top edge held while the button is down: let go in place and the page gets a click where it was pressed; move past the slop and it becomes a window drag the page never sees. A double click and a control-click go straight to the page.
- **`escalation`** — a throwaway extension whose manifest declares one permission and offers another. Declared permissions grant silently; an undeclared one is refused with the declared half intact; allowing grants both; undeclared hosts and match patterns are refused; and a context the manager doesn't recognise is granted nothing. The alert is answered by `escalationAnswerForTesting` — a real modal in an unattended suite would hang the run rather than fail it.
- **`engines`** — the per-feature AI switches and an added engine, against a loopback stand-in for an OpenAI-compatible server. Every feature off and unable to run on a fresh profile; a profile from the single master switch keeping what it had on; the API key in the Keychain and absent from defaults; a loopback engine counted as this Mac and any other naming its host; the model list; an ask-page request carrying the model, the key, the reply's schema and more page text than the on-device budget; a reply read from after a model's thoughts and inside a code fence; a reply with no object giving no answer; a 400 for an unknown model leaving the optional fields in for the next request; a server that answers 400 to the reasoning field, then to the format, being asked again without each; and a private tab refusing an engine off this Mac. Untested: a real LM Studio, OpenAI or OpenRouter server, and the Add Engine sheet.

## Notes on the tricky assertions

- **Live blocking** runs in two halves: first a hand-made one-rule list (does WebKit blocking reach our web views at all?), then the real converted lists (does the ruleset catch a known ad host?). When it breaks, the pair says which half broke.
- **The probe must not use `fetch`'s outcome.** A cross-origin request either fails CORS (looks blocked but wasn't) or resolves opaquely under `no-cors` (looks fine when nothing arrived). The honest signal is Resource Timing: a content-blocked request never reaches the network stack, so it leaves no timing entry. The entry is written when the response _completes_, which is after `fetch` resolves — so the probe waits on a `PerformanceObserver` rather than reading the buffer straight after the await.
- **Probe hosts must resolve.** Pointing a block test at a made-up domain "passes" purely because DNS failed.
- **Performance budgets wait for the blocker to go idle** — measuring while it compiles the full rule set times the machine, not the code. Waiting on `isUpdating` is not enough: that flag only covers the download path, and the launch rebuild compiles through the same queue without it, so the test awaits `ContentBlocker.waitForIdle()` (the work queue itself). The converter budget is set for the unoptimised debug build; release is several times faster and conversion runs off the main actor either way.

- **The traffic lights are tested as real buttons in the sidebar** — superview is `TrafficLightMount.MountView` inside the SwiftUI hosting tree, resting at window x=12, sweeping through 12+ distinct positions mid-animation (genuine per-frame motion, the assertion no external-sync design could pass), and landing back at exactly x=12. Park the pointer first (`CGWarpMouseCursorPosition` — the peek won't dismiss under the cursor); wait for a _stable_ rest x rather than a fixed sleep (the app may start collapsed, and a busy main thread delays the spring); and the theme-widget buttons are **flipped** views, so rect-convert — a point-convert of `.zero` reads their top and throws the y math off by 14pt.
- **Some assertions skip themselves rather than fail on machine state.** The live geolocation path can only be exercised once macOS has granted Artemis location access for the app as a whole. While that answer is `notDetermined`, WebKit waits on the system prompt and never puts the page's question to the app, so there is nothing there to assert about the code — the suite says so in a note and moves on rather than reporting a failure it can't act on. Grant it once in System Settings › Privacy & Security › Location Services to turn the assertion back on. The traffic-light hover and sweep checks do the same when the browser window isn't key: they read rendered pixels and animated positions, and macOS renders an inactive traffic light grey with no glyph and doesn't ask a background app to draw at all. Run the suite without touching the machine.
- **The suite steals focus.** It activates Artemis at the start and drives real UI for several minutes — run it when you're not mid-something, and prefer a quiet machine for the perf budgets (they're best-of-three, but sustained load still skews them).
- **Perf budgets measure fixtures the test owns**, not the developer's session: the display-name budget builds its own query-bearing tab, since its cost depends on the url's shape, and the history budget builds a 5,000-page trail with a real profile's tail of multi-kilobyte urls, since search time is set by the bytes it scans.
- **`chrome.idle` is asserted to be live, not low.** It reads the clock twice and watches it move, allowing for a reset to zero if someone touches the machine mid-test, so it holds for an unattended run too.

## Build configuration

Build Debug while iterating (⌘R in Xcode, or the `xcodebuild` line above): Debug compiles incrementally and in parallel. Release is what ships, and what the perf budgets other than the converter's assume; its build time is whole-module optimisation, not slow type-checking.
